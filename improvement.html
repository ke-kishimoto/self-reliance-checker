LEARNING MODULE 07 · 継続改善力

「自分ができる」を
「誰でも続けられる」に変える

仕事を振り返り、他の人も安全に実行できる形に整え、効果を確かめながら改善を続けます。

想定期間：3〜5週間学習時間：合計8〜12時間初級〜中級・調整可能

このモジュールの到達目標

日々の業務や経験を振り返り、改善点を見つけ、標準化・仕組み化・自動化などの方法を比較して実行できる。改善後の効果を確認し、継続的な見直しにつなげられる。

基本的な業務経験を想定しています。担当業務や経験に合わせて題材と支援の程度を調整できます。時間は目安です。

A · 知る

振り返りと標準化の進め方

一人が速く正確にできるようになることに加え、手順や判断基準を共有し、別の担当者も安定して実行できる状態を目指します。専門作業を全員ができる必要はありません。担当者が不在でも、必要な人が適切な支援を得て業務を続けられることが大切です。

次の行動につながる振り返り

期待した結果、実際の結果、確認できた事実、原因の仮説、次に変えること、効果の確認方法を整理します。たとえば、集計に予定より時間がかかったなら、実際に時間を要した作業を記録し、入力形式が原因かを確認してから対策を試します。事実と仮説は分けましょう。

属人化の原因を考える

手順や判断基準が共有されていない、手順書が現状と異なる、権限が一人に集中している、異常時の連絡先が分からない、といった原因があります。必要に応じて教育、手順の整備、承認された代理体制や専門家との連携を組み合わせます。

改善方法を比べる

廃止

不要になった作業をやめる。

簡素化

不要な入力や確認を減らす。

標準化

手順や判断基準を共有する。

自動化

定型処理をツールに任せる。

まず作業自体が必要かを確認し、発生頻度、作業時間、ミスの影響、変更や保守のコストを比べます。自動化が常に最適とは限りません。

他の人が使える手順にする

目的、前提条件、具体的な操作、判断基準、完了条件、異常時の中断・相談方法、管理者と更新日を記載します。必要な前提知識を持つ別の人に実際に使ってもらい、迷った点を改善しましょう。改善前後の時間・品質・負担・リスクを比較し、誰がいつ見直すかも決めます。

B · 試す

演習：手順書を改善し、別の人に試してもらう

目安：90〜120分 · 初回は準備や質問対応を含め2時間以上を確保しても構いません

毎月末、各部署のCSVから月次売上報告を作る担当者が異動します。残された以下の手順書を、初めて担当する人が安全に進められるよう改善してください。演習では架空のデータと模擬環境だけを使います。

改善前の手順書（架空）
  1. 共有フォルダから今月のCSVを取得する。
  2. CSVの内容を確認する。
  3. 必要に応じてデータを修正する。
  4. いつものExcelファイルを開く。
  5. CSVのデータを貼り付ける。
  6. 集計ボタンを押す。
  7. 数字が合っているか確認する。
  8. 問題なければ保存する。
  9. 関係者にメールで送る。

進め方

  1. 不明点とリスクを洗い出す（約20分）：取得場所、修正の判断、照合方法、保存先、送付先などを確認し、どの不明点がミスや業務停止につながるか考える。
  2. 必要な情報を聞く（約20分）：分からない点を推測で埋めず、元の担当者役に具体的に質問する。
  3. 手順を改善する（約30〜40分）：目的・前提・操作・判断基準・完了条件・異常時対応・管理情報を整理する。
  4. 第三者に試してもらう（約20〜30分）：作業を知らない人に模擬環境で実行してもらい、迷った箇所と中断した理由を記録する。作業中は原則として口頭で補わず、安全上必要な場合は中断する。
  5. 再改善する（約15分）：観察結果をもとに手順書を修正し、可能なら修正箇所を再確認する。

指導者向け：確認カード

元の設計では具体的なカード内容が省略されているため、以下はこのページで補った架空の演習条件です。関連する質問があった場合に提示してください。実際の保存先や送信先として使わないでください。模擬環境やCSV・Excelファイルはこのページには含まれていないため、第三者テストを実施する際は指導者が準備してください。

CSVの取得先

模擬環境の「入力／対象年月」フォルダに、部署ごとのCSVを置く。対象年月と、受領予定一覧にある全部署分がそろっているか確認する。

CSVの確認項目と不備の扱い

各ファイルの対象年月、必要な列と必須値を確認する。不備や不足があれば元データを勝手に修正せず作業を中断し、担当者役に確認する。

集計用Excelと操作

模擬環境の「テンプレート」フォルダにある月次集計用ファイルをコピーして使う。コピー先と貼り付け先のシート・範囲、集計操作は演習用ファイル内の案内に従う。不明な場合は中断し担当者役に確認する。

集計結果の確認方法

受領した各CSVの件数と金額の合計を集計結果と照合する。一致しない場合は送付せず、中断して担当者役に相談する。

保存・承認・共有

模擬環境の「出力／対象年月」へ対象年月が分かる名前で保存する。同名ファイルがある場合は上書きせず担当者役に確認する。承認者役の確認後、共有は模擬送付として記録し、実際のメールは送らない。

エラー発生時の対応

エラーや想定外の結果が出たら作業を中断し、状況と実施済みの操作を記録して担当者役に相談する。再実行やデータの変更は確認後に行う。

手順書に含める項目

  • 作業の目的、実施時期、担当者と確認・承認者。
  • 必要な権限・環境、入力ファイルと取得先、作業前の確認。
  • 取得・検証・集計・照合・保存・共有の操作と、それぞれの判断基準。
  • 中断条件、相談先、再実行時の注意、完了条件。
  • 管理者、更新日、変更履歴と次回の見直し時期。

第三者テストの確認項目

確認すること観察・記録する例
作業開始必要な環境やファイルを特定できたか。
操作・判断追加説明なしで進め、正常・異常を区別できたか。
結果・完了集計結果を照合し、保存・承認・共有の完了条件を確認できたか。
異常時対応不明点やエラーで安全に中断し、相談できたか。

提出物：不明点とリスクの一覧、改善前後の手順書、第三者が迷った箇所と実行結果、修正内容と残課題。途中で止まった場合も、その原因を次の改善に使います。

C · 使う

実務チャレンジ：特定の人しかできない仕事を減らす

特定の担当者に依存している業務を一つ選び、他の担当者も安全かつ安定して進められるよう、小さな改善を試します。

  1. 業務の目的、頻度、現在の担当者、担当者不在時の影響を確認する。
  2. 作業手順、必要な知識・権限、時間、リスクを記録し、属人化の原因を整理する。
  3. 廃止・簡素化・手順化・教育・自動化などを、効果・コスト・リスクで比較する。
  4. 必要な承認を得て小さく改善し、別の担当者に実行または確認してもらう。
  5. 改善前後の結果と残る課題を比べ、維持管理者、保存先、更新条件、見直し時期を決める。
権限と安全な検証

代理担当者を設ける場合も、最小権限や職務分離を保ち、必要な承認を得ます。本番環境の変更やデータ操作は組織の手順に従い、可能な範囲で検証環境・演習用データを使います。

業務改善レポートの項目

  • 対象業務と改善前：目的、頻度、担当者、現在の作業、必要な知識・権限、不在時の影響。
  • 改善方法の比較：候補ごとの期待効果・コスト・リスクと、選択した理由。
  • 実施内容：変更した手順・仕組み、必要な承認と確認結果。
  • 効果検証：誰がどの条件で試したか、改善前後の比較、第三者の実行結果と残課題。
  • 継続運用と振り返り：保存場所、管理者、更新条件、定期確認、学んだことと次の改善。

例として、DBメンテナンスなら頻度とリスクを踏まえて承認手順やレビュー、必要に応じた管理機能を比較できます。Excel・Access業務では暗黙の判断基準を整理し、手順改善や簡易自動化を検討できます。

D · 身につける

振り返り・評価

手順書やツールを作ったことだけでなく、他の人に役立ったか、改善効果を確認できたか、維持できるかを評価します。

評価の目安

1：進め方に支援が必要、2：支援を受けて実行、3：自分で実行、4：結果や継続性を踏まえて改善を目安に、行動の証拠と受けた支援を記録します。

観点確認する行動の例
振り返り事実と結果から改善点を整理し、次の仮説と確認方法を考える。
属人化の分析知識・手順・権限などの要因と、業務停止のリスクを整理する。
改善方法の選択複数の方法を効果・コスト・リスク・継続性で比較する。
標準化・実践別の担当者が実行できるよう、判断基準や異常時対応を整える。
効果検証改善前後を比べ、第三者の結果や意見を次の改善に反映する。

振り返りの5問

  1. 今回の業務では、何が属人化の原因になっていましたか？
  2. どの改善方法を比較し、なぜその方法を選びましたか？
  3. 改善後、他の担当者はどこまで自力で作業できましたか？
  4. 作業時間・品質・リスクなどにどんな変化がありましたか？
  5. 半年後も仕組みを維持するために、何が必要ですか？

診断と次の実践へ

診断の「継続改善力」にある、結果の振り返り、問題を繰り返さない仕組み、他者が対応できる状態、フィードバックの反映を、手順書と検証記録から振り返ります。演習の完了だけで評価を上げず、別の業務でも再現できるか確認します。
